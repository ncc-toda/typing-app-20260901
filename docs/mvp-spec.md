# タイピングアプリ MVP 仕様書

## 1. 概要

### 1.1 目的

IT エンジニアのチャット返信を模した Web タイピングゲーム。相手から届いたメッセージに対し、返信文をローマ字でタイピングして送信し、120 秒間で獲得した「ゲーム内年収」を競う。

### 1.2 対象ユーザー

- タイピング練習をしたい IT エンジニア・学生
- エンジニアあるあるの会話を題材に、楽しみながら入力力を鍛えたい人

### 1.3 世界観

- 今どきの IT 企業（Slack 風）でのやり取り
- 基本トラブルが多めの会社
- 主人公はフルスタック Web アプリ開発部署に配属された新入〜中堅エンジニア
- 主人公の特徴:
  - カタカナ語が大好き。言えば言うほどカッコいいと思っている
  - 1 つの返信につき、1 つは冗談やボケを入れないと気がすまない

---

## 2. ゲーム進行

### 2.1 1 プレイの流れ

1. タイトル画面で難易度を選択
2. 120 秒のカウントダウンが開始
3. 相手メッセージが表示される
4. 返信文（日本語 + ローマ字ガイド）をタイピング
5. 送信完了で年収加算、次のメッセージへ
6. 120 秒経過で結果画面へ

### 2.2 終了条件

- **120 秒の制限時間**が 0 になるとゲーム終了
- 返信途中でも時間切れで終了（未完了分は加算なし）

### 2.3 入力方式

| 項目 | 仕様 |
|------|------|
| 表示 | 日本語返信文 + ローマ字ガイド（現在入力位置をハイライト） |
| 判定 | 一般的な表記揺れを許容（例: `shi` / `si`, `chi` / `ti`, `tsu` / `tu`, `fu` / `hu`） |
| 送信 | 全文正しく入力完了で自動送信（Enter 不要） |
| ミス | 誤入力時は該当位置で止まり、正しいキー入力まで進まない |
| バックスペース | 許可（1 文字戻る） |

### 2.4 出題ルール

- 相手メッセージ → 返信文の 1 セットを「1 ターン」とする
- 120 秒内に可能な限りターンを繰り返す
- 返信文は難易度に応じた長さ・複雑さ
- 1 返信につきボケ 1 つを含む（世界観ルール。UX を阻害しない短さ・タイミングで配置）

## 3. 画面構成

### 3.1 画面一覧

| # | 画面名 | 概要 |
|---|--------|------|
| 1 | タイトル・難易度選択 | アプリ名、難易度 3 段階選択、ゲーム開始 |
| 2 | プレイ中 | Slack 風チャット + タイピング入力エリア + 残り時間・年収 |
| 3 | 結果 | 最終年収、サブ統計、再プレイ・統計画面への導線 |
| 4 | タイピング分析 | 累積の苦手キー・指・動きを確認 |

### 3.2 プレイ中画面の必須要素

- 相手メッセージ（チャットバブル）
- 自分の返信（入力中はリアルタイム反映、完了後は送信済み表示）
- ローマ字ガイド（入力済み / 未入力 / ミス位置の視覚的区別）
- 残り時間（120 秒カウントダウン）
- 現在の累計年収
- 難易度表示

## 4. 難易度

| 難易度 | 想定ペルソナ | 返信の特徴 | 例 |
|--------|--------------|------------|-----|
| 初級 | 新米エンジニア | 短い返信、記号少なめ、初々しい言い回し | 「確認します。少々お待ちください。」 |
| 中級 | 慣れてきたエンジニア | やや長め、@メンション、Issue/PR 番号、軽い Markdown | 「@tanaka さん、PR #123 のレビューお願いします。LGTM ならマージします。」 |
| 上級 | つよつよエンジニア | 長め・複数行、引用・技術用語・記号多め | 複数行の進捗報告 + コードブロック風表記 |

### 4.1 難易度係数（年収計算用）

| 難易度 | 係数 |
|--------|------|
| 初級 | 1.0 |
| 中級 | 1.5 |
| 上級 | 2.0 |

## 5. 出題内容（題材）

### 5.1 カテゴリ

- 確認・レビュー依頼
- バグ報告
- 進捗報告
- 質問
- 顧客への連絡
- @ メンション
- Issue / PR 番号
- 軽い Markdown（`**太字**`, `` `コード` ``, 箇条書き程度）

### 5.2 除外・制限

- URL 全文のタイピング（入力負荷が高すぎる）
- 極端に長いコードブロック
- 特殊記号の連続

### 5.3 会話例（初級）

**相手:** PR #123 のレビューお願いできますか？

**返信:** 確認します。少々お待ちください。あ、差分見たらコメント多すぎて寿司打みたくなってきました。

### 5.4 会話例（中級）

**相手:** @channel 本番で 500 エラー出てます。ログ見てもらえますか？

**返信:** @suzuki さん、了解です。ログ確認します。Nginx のアクセスログ、もうカンファレンスルーム並みに長いですね。

### 5.4 会話例（上級）

**相手:** 顧客から「検索が遅い」と連絡。Elasticsearch のインデックス再構築、今日中に可能？

**返信:** 可能です。`GET /api/search` の p95 が 3s 超えてるので、インデックス再構築 + クエリ最適化を並行します。完了目安 18:00 です。Elasticsearch、今日も元気ですね（棒読み）。

## 6. スコア

### 6.1 メインスコア: ゲーム内年収

返信 1 件完了ごとに加算。最終合計がスコア。

**1 返信あたりの獲得額:**

```
獲得額 = 基礎額 × 難易度係数 × 速度補正 × 正確性補正
```

| 要素 | 説明 | MVP での目安 |
|------|------|--------------|
| 基礎額 | 返信文字数に比例（1 文字あたり 100 円） | 例: 20 文字 → 2,000 円 |
| 速度補正 | 入力速度が速いほどボーナス | 基準 WPM 30 を 1.0、上限 1.5 |
| 正確性補正 | ミスが少ないほどボーナス | 正確率 100% → 1.2、90% → 1.0、80% 未満 → 0.8 |

### 6.2 計測単位

| 指標 | 定義 |
|------|------|
| 入力速度 | 1 分あたりの正しく入力したキー数（CPM: Characters Per Minute） |
| 正確性 | 正しい入力 / 総キー入力 × 100（%） |
| ミス数 | 誤入力したキー数（1 プレイ合計） |
| 最大連続入力数 | ミスなしで連続入力できた最大キー数 |

### 6.3 結果画面の表示

- **メイン:** 最終年収（円、カンマ区切り）
- **サブ:** 入力速度、正確性、ミス数、最大連続入力数
- **その他:** 返信完了数、プレイ時間

## 7. タイピング分析

### 7.1 収集データ（各プレイ）

| 項目 | 内容 |
|------|------|
| 苦手キー | キーごとの入力回数、ミス回数、ミス率 |
| 苦手な指 | 物理キーと指の対応から集計（左手小指〜右手小指） |
| 苦手な動き | 連続 2 キーの遷移（例: `s` → `i`）ごとのミス率 |

### 7.2 統計画面

- 累積データを表示（全プレイの合算）
- 苦手キー TOP 5、苦手な指、苦手な動き TOP 5
- プレイ履歴（日時、難易度、年収）の簡易一覧

### 7.3 MVP で含めない分析

- 高度な統計（相関分析、時系列グラフ）
- キーボード配置の可視化ヒートマップ（将来検討）

---

## 8. データ保存

### 8.1 保存対象

- プレイ結果（日時、難易度、年収、サブ統計）
- キー入力ログ（苦手分析用）
- 累積統計（苦手キー・指・動き）

### 8.2 保存方式（MVP）

- ブラウザの LocalStorage に保存
- サーバー同期は MVP 対象外

---

## 9. MVP 対象外

- ユーザーアカウント・ログイン
- ランキング・ソーシャル機能
- カスタム問題の作成・編集
- 音声・BGM
- モバイル最適化（デスクトップ優先）
- 技術スタック・フレームワークの選定（別途）
