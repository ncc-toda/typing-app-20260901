# UI/UX 方針書

> **ステータス: 確定** — **A案（チャット没入型）** を採用（2026-09-01）

## 1. 採用方向

| 項目 | 内容 |
|------|------|
| 採用案 | **A案: チャット没入型** |
| 参照プロトタイプ | [concept-a-chat.html](../prototypes/concept-a-chat.html) |
| コンセプト | 「仕事中の Slack に返信している」没入感を最優先 |

**選定理由（ユーザー判断）:** 世界観との一致、Slack 風チャット体験を重視。

---

## 2. デザイン原則

| 原則 | 内容 |
|------|------|
| 世界観 | 今どき IT 企業、Slack 風チャット、トラブル多めの会社 |
| カラー | 白ベース + ビビッドな多色（紫 `#611f69`、青 `#1264a3`、緑 `#2eb67d`、赤 `#e01e5a`、黄 `#ecb22e`） |
| トーン | カラフルでポップ。堅すぎないが、業務ツール感は残す |
| タイポ | 本文: システム UI 系（Segoe UI / Hiragino Sans）。ローマ字ガイド: 等幅（Consolas） |
| レイアウト | デスクトップ優先。左サイドバー + メインチャット。狭い画面ではサイドバーを折りたたみ |

---

## 3. 画面別 UI 仕様

### 3.1 タイトル・難易度選択

**レイアウト:** 中央配置、白〜薄紫グラデーション背景

| 要素 | 仕様 |
|------|------|
| ロゴ | 「Reply Rush」— 紫〜青グラデーション文字 |
| サブコピー | 「エンジニアのチャット返信を、120秒で打ち倒せ」 |
| 難易度 | 3 カード横並び（初級 🌱 / 中級 ⚡ / 上級 🔥）。選択時は紫ボーダー |
| CTA | 「ゲーム開始（120秒）」— 紫ボタン |

**意図:** ゲーム感より世界観の入口。B 案のような大きなスコアプレビューは入れない。

### 3.2 プレイ中（メイン画面）

**レイアウト:** Slack 風 2 カラム

```
┌──────────┬──────────────────────────────────────────┐
│ Sidebar  │  # incidents          ⏱ 87秒  💰 ¥124,500 │
│ 🚀 Trouble│ ───────────────────────────────────────── │
│ Inc.     │  [PM] 相手メッセージ                      │
│          │  [YOU] 自分の返信（入力中）               │
│ #incidents│ ───────────────────────────────────────── │
│ #dev-team│  返信を入力                               │
│ #random  │  日本語返信文                             │
│ #general │  ローマ字ガイド（done / current / pending）│
└──────────┴──────────────────────────────────────────┘
```

| 要素 | 仕様 |
|------|------|
| サイドバー | 幅 220px、紫系 `#3f0e40`。ワークスペース名 + チャンネル一覧 |
| チャットヘッダー | チャンネル名 + **控えめ HUD**（残り時間・累計年収） |
| メッセージ | アバター + 名前 + 時刻 + バブル。自分は右寄せ・青系背景 |
| @mention | 青 `#1264a3`、太字 |
| 入力エリア | チャット下部コンポーザー風。日本語 + ローマ字ガイド |
| ローマ字状態 | 完了=緑 / 現在=黄ハイライト / 未入力=グレー |

**意図:** 年収・タイマーは見えるが主役にしない。チャット返信に集中できる UI。

### 3.3 結果

**レイアウト:** 中央カード、白背景、シャドウ

| 要素 | 仕様 |
|------|------|
| 見出し | 「120秒 終了！」 |
| メイン | 最終年収（紫、大きめだが B 案ほど派手ではない） |
| サブ統計 | 2×2 グリッド（CPM / 正確性 / ミス数 / 最大連続） |
| 補足 | 返信完了数、難易度 |
| CTA | 「もう一度」「統計を見る」 |

**意図:** 達成感は出すが、祝福演出（B 案の 🎉 等）は控えめ。

### 3.4 タイピング分析

**レイアウト:** 単一カラム、セクション分割

| セクション | 内容 |
|------------|------|
| 苦手キー TOP 5 | キー、入力/ミス回数、ミス率 |
| 苦手な指 | 指名 + ミス率バー |
| 苦手な動き TOP 5 | キー遷移 + ミス率 |

**意図:** C 案の表形式よりシンプル。A 案プロトタイプのセクション + バー形式を踏襲。

## 4. コンポーネント

| コンポーネント | 説明 |
|----------------|------|
| Sidebar | ワークスペース名、チャンネルリスト、アクティブ状態 |
| ChatBubble | 相手/自分、avatar、時刻、mention 対応 |
| ChatHeader | チャンネル名 + MinimalHUD（Timer + Salary） |
| RomajiGuide | done / current / pending の 3 状態 |
| DifficultyCard | 選択状態、emoji、ペルソナ名 |
| SalaryDisplay | 円表示、カンマ区切り。加算時は控えめなカウントアップ |
| TimerDisplay | 秒数表示（ヘッダー内、小さめ） |
| AnalysisSection | 苦手キー/指/動きのリスト + ミス率バー |

---

## 5. フィードバック・アクセシビリティ

- **ミス時:** 入力停止。current 位置の視覚的フィードバック（赤フラッシュ等）
- **返信完了:** チャットに送信済みバブル表示 + 年収の控えめな加算表示
- **時間切れ:** 結果画面へ自動遷移
- **コントラスト:** WCAG AA を目安
- **キーボード:** タイピング主体。Tab 操作はタイトル・結果画面程度

---

## 6. 他案から取り込まないもの（A案方針）

| 案 | 不採用要素 |
|----|------------|
| B案 | 大型 HUD、コンボバッジ、グラデーションバー、🎉 演出 |
| C案 | 大型入力エリア、次キー提示、リアルタイム苦手予告、進捗バー |

※ MVP 実装時に「年収の見えにくさ」が問題になった場合のみ、B 案の HUD 要素を**最小限**追加検討。
